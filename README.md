# 社区公益集市：摊主审核 · 摊位分配 · 收款与捐赠平台

面向社区举办公益集市的全流程管理系统，覆盖 **摊主报名 → 社区审核 → 智能摊位分配 → 入场二维码/物资清单 →
现场核销/巡检/投诉/异常 → 收款流水/捐赠核对 → 统一活动档案 → 复盘与招商建议 → 居民公益公示**。

- 后端：Spring Boot 3.2 + Spring Data JPA + MySQL 8（本地开发默认 H2 内存库，零依赖启动）
- 前端：Vue 3 + Vite + Element Plus + Pinia + ECharts + qrcode
- 交付：Dockerfile（前端/后端）+ docker-compose（MySQL + 后端 + Nginx 前端）一键启动

## 一、功能与需求对应

| 业务环节 | 实现 |
| --- | --- |
| 摊主报名 | 售卖品类（手作/二手/食品/公益义卖/商业）、食品资质、公益捐赠比例、用电/桌椅需求、亲子摊位、收款方式与账户 |
| 社区审核 | 按五类活动规则给出校验提示（食品资质不全建议驳回、信用<80 审慎通过等）；通过后自动生成**摊主入场二维码**与**物资领取清单** |
| 智能摊位分配 | 综合①摊位大小②人流等级③供电容量④噪音敏感区⑤同类品类相邻冲突⑥公益属性，并叠加摊主**信用分、历史捐赠、食品风险、亲子属性**打分；输出每摊的分配理由；支持手动改派/释放 |
| 现场核销 | 扫码（或点选）核销入场，返回摊主信息+物资清单；一键登记物资发放 |
| 现场巡检 | 记录实际售卖内容、临时换品、实测功率；卖品不符/用电超载**自动生成异常档案并扣信用分** |
| 现场换品审核 | 摊主现场临时增项（如二手玩具摊增加自制蛋糕），工作人员记录**换品内容、食品资质、摊位条件（供电/食品区/卫生）与现场照片**；资质条件齐全则**允许售卖并更新品类、用电与食品安全提示**；资质不足则**责令下架（必须保留照片）、记录已售数量与退款、登记食品风险事件并扣信用**，摊主被标记食品风险——**后续食品类报名受限、下次报名需管理员提前复核** |
| 投诉处理 | 登记、处理闭环；投诉成立扣摊主信用 |
| 提前离场 | 登记异常并扣信用分，计入履约复盘 |
| 收款统计 | 按摊位登记现金/微信/支付宝流水（凭证号），实时汇总营业额 |
| 捐赠核对 | 应捐 = 流水合计 × 承诺比例；实捐一致才确认，不一致自动生成「捐赠金额与流水不一致」异常 |
| 七类异常 | 资质不完整、卖品不符、同类冲突、用电超载、提前离场、捐赠不符、公益组织要求公示明细（+其他），统一归档 |
| 食品风险处置 | 现场换品资质不足下架归入「现场换品食品风险下架」异常（新增第八类异常类型），风险标记跟随摊主，影响食品报名、摊位分配打分与下次招商建议 |
| 统一活动档案 | 报名、审核、摊位、收款、捐赠、投诉、异常、公示在同一活动档案中按摊主串联 |
| 复盘 | 公益金额 vs 目标、客流、品类结构图表、到场率/提前离场、摊主履约捐赠榜、信用红榜、**下次招商建议** |
| 居民公示 | 活动结束后对居民公开总捐赠、营业额、用途、履约、异常处理，并可按公益组织要求公开**逐摊位捐赠明细**（无需登录） |
| 摊主信用 | 初始 100 分，入场/足额捐赠加分，违规扣分；信用影响后续摊位分配，摊主可查看信用流水 |

## 三、一键启动（Docker Compose，推荐）

前置：安装 Docker 与 Docker Compose。

```bash
cd 154-b
docker compose up --build
```

启动后：

- 前端（Nginx）：http://localhost:8088
- 后端 API：http://localhost:8080
- MySQL：localhost:3306（root/root，库 charity_market，表结构由 JPA 自动创建）

居民公示端：浏览器打开 http://localhost:8088 → 点「居民公示端」，或直接访问 `#/public`（需先在后台把活动置为「已结束」并发布公示）。

## 四、本地开发启动（无需 Docker / MySQL）

### 4.1 后端（默认 dev  profile 使用 H2 内存库）

```bash
cd backend
mvn spring-boot:run
# 或：mvn package && java -jar target/charity-market-1.0.0.jar
```

- 服务地址：http://localhost:8080
- H2 控制台：http://localhost:8080/h2-console（JDBC URL `jdbc:h2:mem:charity_market`，用户名 `sa`，密码空）
- 连接本地 MySQL：用 docker profile 启动并覆盖环境变量，例如
  `SPRING_PROFILES_ACTIVE=docker DB_URL=jdbc:mysql://localhost:3306/charity_market?... DB_USERNAME=root DB_PASSWORD=root mvn spring-boot:run`

### 4.2 前端

```bash
cd frontend
npm install
npm run dev      # http://localhost:5173 ，已配置 /api 代理到 8080
```

## 五、推荐验证路径（业务走查脚本）

1. **管理员登录** → 工作台选择「2026 秋季社区公益集市」。
2. **活动与公益目标**：查看公益目标与 8000 元筹款目标（可新建活动）。
3. **摊位平面图**：查看 4×5 分区（入口/中心/边角/食品区、供电与噪敏标记），可增删改或批量生成。
4. **报名审核**：5 个合规摊位「通过」（系统生成入场码）；小白烘焙资质不完整「驳回」。
5. **智能分配**：点「一键智能分配」→ 公益义卖 100% 捐赠进入入口高人流位；食品摊强制进入食品区并满足供电；查看每个摊位的分配理由；可手动改派。
6. **工作人员登录**：
   - **核销入场/物资**：扫/输摊主码（或点待入场列表），查看物资清单；用 `laowang` 核销并确认物资发放。
   - **巡检/临时换品**：给老王凉粉登记「实际油炸臭豆腐、与报名不符、实测 1500W（超 1000W 容量）」，系统自动生成两条异常并扣信用。
   - **现场换品审核**（本功能）：
     1. 先在「报名审核」通过 `mayi`（蚂蚁闲置铺，二手玩具），完成智能分配并核销入场。
     2. 进入「现场换品审核」→ 选蚂蚁闲置铺 → 登记**临时新增「自制奶油蛋糕」**，品类改为食品、资质填「资质不完整（健康证办理中）」、摊位条件按实际（非食品区/无供电/卫生不具备）填写并提交。
     3. 点「允许售卖」→ 系统拦截：食品资质不齐全不得放行；不带照片直接「要求下架」→ 系统拦截：下架必须保留现场照片。
     4. 重新登记一条并填照片编号（如 `photo_001.jpg,photo_002.jpg`）→「要求下架」，填**已售 3 份、需要退款**及退款说明 → 信用 −20（102+2−20=84）、生成「现场换品食品风险下架」异常、摊主被标记**食品风险 + 下次报名需提前复核**。
     5. 用 `mayi` 登录：「我的换品审核」可见下架记录、已售数量与退款说明，「我的信用」可见扣分；对**新活动报名食品类被直接拒绝**，报名二手可正常提交。
     6. 管理员在「账号管理」找到蚂蚁闲置，点「复核通过解除」后，`mayi` 可重新报名食品类；管理员下次正常审核通过其报名也会自动取消强制复核标记。
     7. 放行路径：通过并核销 `shanyi`（公益义卖），登记新增食品（资质齐全、卫生合格）→ 先因不在食品区被拦截，管理员在分配页把其**改派到食品区空闲摊位**后重新登记并「允许售卖」→ 报名品类更新为食品、用电与**食品安全提示**同步更新（核销页/摊主入场码页可见），主动报备合规信用 +2。
   - **投诉与异常**：登记一条居民投诉并闭环；在异常页把现场客流更新为 1280。
   - 对老王摊点**提前离场**。
7. **收款与捐赠核对**：给老王凉粉登记流水 1000 元（承诺 20%，应捐 200）；先核 150 元 → 自动「流水不符」异常；再核 200 元 → 已核对，信用加分。
8. **活动统一档案**：在活动列表→「档案」查看报名/审核/摊位/收款/捐赠/投诉/异常/公示同档归集。
9. **复盘**：查看公益金额 vs 目标、客流、品类饼图、履约捐赠榜、信用变动与「下次招商建议」。
10. **居民公示**：活动置为「已结束」→「发布居民公示」，填写用途/履约/异常处理并勾选逐摊位明细后发布；退出登录进入「居民公示端」查看总捐赠、用途与明细。
11. **摊主端**：`laowang` 登录查看「我的入场二维码、物资清单、收款捐赠、信用流水」；新用户可自助注册并报名。

## 七、工程结构

```
154-b/
├── docker-compose.yml          # MySQL + backend + frontend(Nginx)
├── backend/                    # Spring Boot 工程
│   ├── Dockerfile
│   └── src/main/java/com/community/market/
│       ├── common/             # 统一返回、异常处理
│       ├── config/             # Web 配置、演示种子数据
│       ├── security/           # 简易 Token 会话与鉴权拦截器
│       ├── domain/             # 枚举 + JPA 实体
│       ├── repository/         # Spring Data 仓储
│       ├── dto/                # 请求 DTO
│       ├── service/            # 审核/智能分配/现场/换品审核/财务/档案复盘公示/信用
│       └── controller/         # REST 接口（管理/现场/摊主/居民公开端）
└── frontend/                   # Vue 3 工程
    ├── Dockerfile
    ├── nginx.conf
    └── src/
        ├── api/ stores/ dict.js composables/ components/
        ├── layouts/            # 按角色菜单的主布局
        └── views/              # admin(管理) staff(现场，含现场换品审核) vendor(摊主，含我的换品审核) + 居民公开端
```

> 说明：系统内鉴权为演示用内存 Token（重启失效），密码明文存储仅用于作业演示，生产环境请替换为 JWT/Redis 会话与加密存储。
